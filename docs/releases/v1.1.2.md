# v1.1.2

修复 `r36-p1` 等单段数字发布标签无法编译为漏洞版本范围的问题。

- 通用解析识别完整的 `r`/`R` 数字发布标签，如 `r36`、`r36-p1`、`R36-p10` 和 `r36.1-p2`。只移除包装前缀，原始输入仍可追溯。
- 根包的普通比较、GenericOSVersion、精确匹配、区间、固定修复版本与 versionrange 的 normal 比较共享此能力。
- 保留完整后缀与数字自然顺序：`r36-p1 < r36-p2 < r36-p10`。不将 p1 改写为小版本，不额外推断补丁发布语义。
- 沿用已有正式版和后缀的顺序：`r36-p10 < r36`；显式 MatchMain 仍忽略后缀。OS 原生算法、Git/custom、范围开闭边界均保持原有约定。
- 转换以完整标签为前提，任意前置文字、路径及范围控制字符不使用此转换；既有 r1v60/r1rv78 规则及完整 commit 处理不受影响。

验证：全部包测试、竞态检查和 go vet；覆盖精确 CPE 标签、两种通用版本类型、结构化 normal、固定修复边界、项目门禁及不可排序标识。
